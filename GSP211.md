# GSP211 – Multiple VPC Networks

Everything in this tutorial is done from Cloud Shell, including the steps the lab does in the Console. The checker only looks at the resources, so the result is the same.

## Known lab traps (read first)

1. Region_1, Region_2 and the zone are different in every lab instance. The Setup block reads them from the VMs the lab already created for you.
2. The lab's privatenet-vm-1 command has an empty `--zone=`, so it fails as written. Fixed below.
3. Nothing in this lab deletes anything, so there's no cleanup trap. You can run every block and then click all the checks. The checker can lag, so wait 30–60 seconds and click again if one shows 0.
4. Big pastes get garbled in Cloud Shell. Paste one block at a time.

## Setup (automatic)

```bash
gcloud compute instances list --filter="name=mynet-vm-1" --format="value(zone.basename())" > ~/zone
gcloud compute instances list --filter="name=mynet-vm-2" --format="value(zone.basename())" > ~/zone2
cat ~/zone | rev | cut -d- -f2- | rev > ~/region1
cat ~/zone2 | rev | cut -d- -f2- | rev > ~/region2
head ~/zone ~/region1 ~/region2
```

Compare these with your lab text. ~/region1 should match Region_1, ~/region2 should match Region_2, and ~/zone should match the zone for managementnet-vm-1. If any of them differ, overwrite that value, for example `echo us-east1-b > ~/zone`.

## Task 1 – Custom mode VPC networks with firewall rules

Block 1 – managementnet and its subnet:

```bash
gcloud compute networks create managementnet --subnet-mode=custom
gcloud compute networks subnets create managementsubnet-1 --network=managementnet --region=`cat ~/region1` --range=10.130.0.0/20
```

Check my progress: Create the managementnet network

Block 2 – privatenet and its two subnets:

```bash
gcloud compute networks create privatenet --subnet-mode=custom
gcloud compute networks subnets create privatesubnet-1 --network=privatenet --region=`cat ~/region1` --range=172.16.0.0/24
gcloud compute networks subnets create privatesubnet-2 --network=privatenet --region=`cat ~/region2` --range=172.20.0.0/20
gcloud compute networks subnets list --sort-by=NETWORK --filter="network~managementnet OR network~privatenet"
```

Check my progress: Create the privatenet network

Block 3 – firewall rule for managementnet:

```bash
gcloud compute firewall-rules create managementnet-allow-icmp-ssh-rdp --direction=INGRESS --priority=1000 --network=managementnet --action=ALLOW --rules=icmp,tcp:22,tcp:3389 --source-ranges=0.0.0.0/0
```

Check my progress: Create the firewall rules for managementnet

Block 4 – firewall rule for privatenet:

```bash
gcloud compute firewall-rules create privatenet-allow-icmp-ssh-rdp --direction=INGRESS --priority=1000 --network=privatenet --action=ALLOW --rules=icmp,tcp:22,tcp:3389 --source-ranges=0.0.0.0/0
gcloud compute firewall-rules list --sort-by=NETWORK
```

Check my progress: Create the firewall rules for privatenet

## Task 3 – Explore connectivity (not scored)

Block 1 – save the IP addresses:

```bash
gcloud compute instances list --filter="name=mynet-vm-2" --format="value(networkInterfaces[0].accessConfigs[0].natIP)" > ~/ext-mynet2
gcloud compute instances list --filter="name=managementnet-vm-1" --format="value(networkInterfaces[0].accessConfigs[0].natIP)" > ~/ext-mgmt
gcloud compute instances list --filter="name=privatenet-vm-1" --format="value(networkInterfaces[0].accessConfigs[0].natIP)" > ~/ext-priv
gcloud compute instances list --filter="name=mynet-vm-1" --format="value(networkInterfaces[0].networkIP)" > ~/int-mynet1
gcloud compute instances list --filter="name=mynet-vm-2" --format="value(networkInterfaces[0].networkIP)" > ~/int-mynet2
gcloud compute instances list --filter="name=managementnet-vm-1" --format="value(networkInterfaces[0].networkIP)" > ~/int-mgmt
gcloud compute instances list --filter="name=privatenet-vm-1" --format="value(networkInterfaces[0].networkIP)" > ~/int-priv
head ~/ext-* ~/int-*
```

Block 2 – from mynet-vm-1, ping the external IPs. All three work:

```bash
gcloud compute ssh mynet-vm-1 --zone=`cat ~/zone` --quiet --command="ping -c 3 `cat ~/ext-mynet2`; ping -c 3 `cat ~/ext-mgmt`; ping -c 3 `cat ~/ext-priv`"
```

The first time, it generates an SSH key. That's normal.

Block 3 – from mynet-vm-1, ping the internal IPs. Only mynet-vm-2 works; the other two show 100% packet loss:

```bash
gcloud compute ssh mynet-vm-1 --zone=`cat ~/zone` --quiet --command="ping -c 3 `cat ~/int-mynet2`; ping -c 3 -W 2 `cat ~/int-mgmt`; ping -c 3 -W 2 `cat ~/int-priv`"
```

Quiz answer: "Which instance(s) should you be able to ping from mynet-region-1-vm using internal IP addresses?" Select only the third option, mynet-region-2-vm. It's on the same VPC network. The other two are on separate VPC networks.

## Task 4 – VM instance with multiple network interfaces

```bash
gcloud compute instances create vm-appliance --zone=`cat ~/zone` --machine-type=e2-standard-4 \
  --network-interface=subnet=privatesubnet-1 \
  --network-interface=subnet=managementsubnet-1 \
  --network-interface=subnet=mynetwork
```

Check my progress: Create a VM instance with multiple network interfaces

Optional – explore the interfaces and routes from inside vm-appliance:

```bash
gcloud compute ssh vm-appliance --zone=`cat ~/zone` --quiet --command="ip -br addr; ping -c 3 `cat ~/int-priv`; ping -c 3 privatenet-vm-1; ping -c 3 `cat ~/int-mgmt`; ping -c 3 `cat ~/int-mynet1`; ping -c 3 -W 2 `cat ~/int-mynet2`; ip route"
```

What to expect: the pings to privatenet-vm-1 (by IP and by name), managementnet-vm-1 and mynet-vm-1 work. mynet-vm-2 fails, because its subnet is in Region_2 and isn't in vm-appliance's routing table, so that traffic leaves through eth0 on privatenet. The lab uses `sudo ifconfig`, which isn't installed on newer images. `ip -br addr` shows the same three interfaces (eth0, eth1, eth2).
